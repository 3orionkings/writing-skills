# Reading on public works

A first cut at a reading list on how public works get built quickly.

- [Title A](https://example.org/reading-0) The fix was boring and it worked.
- [Title B](https://example.org/reading-1) Reviewers started reading the smaller changes properly instead of skimming them.
- [Title C](https://example.org/reading-2) The team stopped arguing about tools once the queue had an owner.
- [Title D](https://example.org/reading-3) A shorter path through the code made the next change cheaper as well.
- [Title E](https://example.org/reading-4) Support could answer the question in the ticket instead of escalating it.
- [Title F](https://example.org/reading-5) The release notes got shorter because there was less to explain.
- [Title G](https://example.org/reading-6) Most of the delay came from a queue that nobody owned.
- [Title H](https://example.org/reading-7) The old dashboard showed averages, and averages hide the slow requests at the tail.
- [Title I](https://example.org/reading-8) Customers noticed the faster checkout before the metrics did.
- [Title J](https://example.org/reading-9) Nobody had written down who could approve a refund, so every refund waited for the same two people.

This list leaves out the engineering manuals. It is a first cut and still in progress.
