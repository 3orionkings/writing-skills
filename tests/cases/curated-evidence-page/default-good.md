# Fast builds

This page collects public works finished quickly, with the elapsed days computed for each.

**Project 1.** Customers noticed the faster checkout before the metrics did. The work took 30 days from start to finish.
*Source: [primary account 1](https://example.org/source-1)*

**Project 2.** Nobody had written down who could approve a refund, so every refund waited for the same two people. The work took 47 days from start to finish.
*Source: [primary account 2](https://example.org/source-2)*

**Project 3.** The fix was boring and it worked. The work took 64 days from start to finish.
*Source: [primary account 3](https://example.org/source-3)*

**Project 4.** Reviewers started reading the smaller changes properly instead of skimming them. The work took 81 days from start to finish.
*Source: [primary account 4](https://example.org/source-4)*

**Project 5.** The team stopped arguing about tools once the queue had an owner. The work took 98 days from start to finish.
*Source: [primary account 5](https://example.org/source-5)*

**Project 6.** A shorter path through the code made the next change cheaper as well. The work took 115 days from start to finish.
*Source: [primary account 6](https://example.org/source-6)*

**Project 7.** Support could answer the question in the ticket instead of escalating it. The work took 132 days from start to finish.
*Source: [primary account 7](https://example.org/source-7)*

**Project 8.** The release notes got shorter because there was less to explain. The work took 149 days from start to finish.
*Source: [primary account 8](https://example.org/source-8)*

The northern rail spur, approved in 2009, was still unfinished after 4,800 days. Most of the delay came from a queue that nobody owned.

This page leaves out private projects and anything without a primary source. Works offering hypotheses are listed separately, none endorsed.

Send corrections or additions, with a source.
