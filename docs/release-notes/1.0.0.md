# Release notes: 1.0.0 (19 October 2026)

Before the first release, the twelve skills went through an audit that found 24 defects in the shared linter, the shared structure checker, the humanizer and the individual forms. This page records how each was fixed. The test suite written for the audit has 128 tests: the skills as they stood before the audit passed 32 of them, and this release passes all 128. The skills stayed neutral through the fixes: no author or profession defaults were added, and the rules on invented facts, verbatim citations and text-only delivery did not change.

Packaging for Claude Code, Codex and ChatGPT was added after the audit and is described in the main [CHANGELOG](../../CHANGELOG.md).

## The 24 items

| # | What changed |
|---|---|
| 1 | `lint.py` has an allowlist of fixed collocations (ten from the audit plus "statistically significant" and "significant figures"), which are never flagged. Navigate, robust, dynamic, leverage, enhance, elevate, foster, harness, landscape, comprehensive and facilitate are soft unless a figurative frame matches ("navigate the complexities", "the AI landscape", "leverage our data") or another tell sits in the same sentence. |
| 2 | "Deep dive" and "step-by-step" are soft. A dash between two digits (2019–2021) is a range and is not flagged. Under `--allow-markdown`, arrows and mathematical signs are left alone; emoji stay hard. |
| 3 | Six new soft checks: the two-sentence negative parallelism with any repeated pronoun ("You're not X. You're Y.", "We don't X. We Y."), "not because X, but because Y", aphorism formulas ("X is the currency of Y"), copula avoidance ("serves as a"), gap-filling speculation, and a heading restated in the line below it. Blockquotes under a heading are skipped, so the boxed restatements technical-principles-essay asks for are not flagged. |
| 4 | `lint.py` is the single vocabulary source; `lint.py --list` prints it by severity. Section 2 of `ai-tells.md` now describes the linter's tiers instead of keeping its own list. Words the catalogue named but the linter ignored (just, journey, emphasizing, essential, highlight, key as an adjective, perfectly, significant, valuable) are now soft findings, and so are the catalogue's false ranges, vague attribution and "on the one hand". The humanizer and the rules file name examples and point to `--list`. A test lints every word the old catalogue named. |
| 5 | The humanizer has a Formatted content section: a loaded style skill's template and its named departures govern structure; a README, docs page, web page, slides or PR description keeps its headings, lists, links and call to action; the no-markdown rule is for emails, letters, messages and running prose. Lint with `--allow-markdown` in both cases. |
| 6 | The humanizer description no longer says the rules govern all of Claude's replies. Only replies that are drafts for the user to send follow them, and code, commands, commit messages and data are excluded. |
| 7 | Dashes are banned by default. `--author-sample FILE` (or `--max-dashes-per-1000 N`) makes each dash soft until the draft goes past the author's own rate, then adds one hard finding. Documented in the humanizer, `ai-tells.md` and the rules file. |
| 8 | Workflow step 4 and the rules file say a hard finding on a literal or trade term is cleared by leaving the term. |
| 9 | New step 3: lint the draft first; if it is clean and specific, make the minimal edit and return the rest as written. |
| 10 | The one permitted note (a citation that looks wrong) goes on one line above the text. Nothing goes after it. |
| 11 | "The ask goes in the first or second sentence" now applies to request emails and letters only. |
| 12 | `style_check.py` finds where the body ends: the first footnote definition, a References, Sources, Citation, Endnotes, Notes, Acknowledgements, Related reading, Further reading, Bibliography or Appendix heading, or a trailing Published or Updated footer. Close, opening and heading checks read the body only. |
| 13 | `style.json` supports `variants`; `style_check.py` takes `--variant NAME` and `--list-variants`. Nineteen variants across eight skills, including every one the audit found failing. Each workflow names its variants. Variant length ranges are the ranges the prose gives. |
| 14 | The title check no longer passes any title of four words or fewer; it wants five words or fewer that start on an imperative or carry a claim verb, and "prioriti", "harness" and "breaking" are gone from its list. `headings_assert` checks every heading. Numbers are counted in body prose only, without heading numerals, list markers, footnote markers or URLs. "To be clear" no longer counts as an objection. A bold thesis must be a bold run of four words or more, so a bold name does not count. |
| 15 | New keys: `figures: "none"` (mechanism-essay), `paragraphs` 19 to 30 (principle-column), question headings and a references section (patterns-survey), `require_definition_first_sentence` (taxonomy-explainer), `bold_thesis_per_section` (reportage-deep-dive), `figure_captions_short` for field-guide's under-ten-word or colon-introduced captions. Thresholds now match the prose: thesis-first-note first sentence and one-idea-post close under twelve words (11 or fewer), principle-column 600 to 1,700 words. |
| 16 | A "Departures from the humanizer" section in reportage-deep-dive, thesis-first-note, technical-principles-essay, field-guide, mechanism-essay and strategy-pattern-essay says what the form allows, where, and that the soft finding on it can stay. Dashes are not readmitted: the forms that used them follow the humanizer's author-rate rule. |
| 17 | mechanism-essay teaches the mechanism with a labelled hypothetical whose round numbers never carry into a claim about the real case. |
| 18 | "If you don't have" fallbacks in mechanism-essay, thesis-first-note, field-guide, reportage-deep-dive, technical-principles-essay, principle-column, one-idea-post and patterns-survey. principle-column now says two to six earlier pieces in both places. |
| 19 | Reader quotes, contributions, thanks, course pointers, hiring lines, the paywall and the teaser appear only if the user supplies them, in the six skills named plus strategy-pattern-essay and mechanism-essay (which had thanks and acknowledgements). Their omission is gone from the failure lists. |
| 20 | Source-writer specifics are bracketed placeholders: the six named plus 7,600 days and 37 times the cost, 143 and 491, a dozen samples and about 100 labelled examples, 200 and 400 samples at 3 percent, a 1965 paper and a 2008 essay, a 1993 mailing-list post, six tooltip states, a Friday night twenty years ago, six-month-old evidence, and the source writers' own coined terms and theses. Every style skill and the rules file say never to reuse an example's specifics. |
| 21 | A research step (open every source before citing it, record the exact figure and where it appears, mark anything unverified and keep it out until the user confirms) in taxonomy-explainer, patterns-survey, curated-evidence-page, technical-principles-essay and reportage-deep-dive. taxonomy-explainer links or describes figures unless the user has the rights; sentence one is the definition, and a history follows it. |
| 22 | Every style description has a "Not for:" line pointing to the right sibling. Descriptions were tightened to make room; the longest is 977 characters, under the 1,024 limit, and a test enforces it. |
| 23 | `tools/sync_shared.py` copies `shared/lint.py`, `shared/style_check.py` and `shared/human-writing-rules.md` into the skills and exits 1 if any copy differs (`--check` verifies without copying). `tools/package.py` refuses to build when the check fails. The stale "ignore any author-specific defaults" line is gone. |
| 24 | `tests/` holds 45 lint tests, 56 style-check drafts (good and bad per check and per variant, generated by `build_cases.py`), 23 wording checks on the SKILL.md and reference files, and 4 shared-file checks. |

## Also fixed, found while testing

- The numbered-outline check only saw a numbered list on the very first body line, because its pattern was anchored to the start of the joined text. It now reads the first 40 body lines.
- The full-sentence caption check failed taxonomy-explainer's own skeleton caption, which ends in "(Image source: Author et al. YEAR)". It now strips a trailing credit, and it also accepts an italic caption on the line under the image, which is how reportage-deep-dive describes its captions.
- Headings inside fenced code blocks no longer count as headings, and end-matter headings such as Notes or References no longer break a no-headings form.
- curated-evidence-page's entry check reads each entry's whole block and is split into links and numbers, so the reading list can require links without numbers.
- Both scripts now reject unknown options instead of ignoring them or reading them as file names.

## Judgement calls

- "Under twelve words" became 11 or fewer in the config, and thesis-first-note's workflow now says "twelve words or more" where it used to say "more than twelve".
- thesis-first-note's base spec checks no headings and no bullets, as the headless note requires; the headed essay is `--variant headed-essay`.
- Where the prose gives no number, I chose one and wrote it into the variant's description: twelve question headings for the FAQ's "dozens", eight to fifteen items for the list essay, at least three numbered confessions, and at least two numbers and one link for the short note.
- patterns-survey reproduced papers' figures the same way taxonomy-explainer did, so it got the same link-or-describe rule.

## Left alone, worth a look

- reportage-deep-dive and field-guide list "no typos" among the ways an imitation fails. The skills mean "leave the author's typos", but the line can be read as an instruction to add some, which the humanizer forbids.
- The figurative frames and the claim-verb list are heuristics. The tests pin every case the audit found; other sentences will still slip through or get flagged.

## Commands

```
python3 tools/sync_shared.py          # after editing anything in shared/
python3 tests/build_cases.py          # after editing the style-check drafts
python3 -I -B tests/run_tests.py      # the skills in plugins/writing-skills/skills
python3 -I -B tests/run_tests.py --skills DIR --tree DIR --label NAME --out FILE   # any other copy
python3 tools/validate.py             # manifests, versions and skills agree
python3 tools/package.py --out DIR    # .skill files and writing-skills.zip
```
